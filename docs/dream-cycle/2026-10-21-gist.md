# Flywheel-Promotion SOTA Report — 2026-10-21

TL;DR: `@metaharness/flywheel`'s signed-receipt canonicalizer collapsed `NaN`, `Infinity`,
`-Infinity`, and `null` into the identical byte string, so a 2026 agent-promotion trust
check (`sealedFieldsAuthentic`) could be defeated with no signing key. Fixed, additively,
with a non-vacuous red→green proof and an independent critic's confirmation.

## MetaHarness Current Capability

`canon()` (packages/flywheel/src/receipts.ts) is the ONE canonicalization primitive every
signed `PromotionReceipt`, `verifyReplayBundle`'s 8-point replay check, and
`multigeneration-proof.ts`'s (ADR-318) reviewer-attestation binding route through. It
recursively builds a sorted-key JSON string and falls through to `JSON.stringify` for
scalars. `JSON.stringify(NaN) === JSON.stringify(Infinity) === JSON.stringify(-Infinity)
=== JSON.stringify(null) === "null"` (ECMA-262's own defined behavior) — so pre-fix,
`canon()` inherited a 4-way collision at exactly the values a canon-EQUALITY check exists
to protect. `sealedFieldsAuthentic` (replay.ts) compares `canon(payload[k]) !==
canon(live(c))` for `primaryDelta`/`anchorScore`/`baselineScore`/`candidateScore` — a live
field edited (no key needed) from a signed `NaN` to `null`, or `Infinity` to `NaN`, passed
as "authentic."

## Hypothesis

Given a signed receipt or sealed-field-authenticity check that compares a live numeric
field against its `canon()`-encoded signed counterpart, when `canon()` encodes NaN,
Infinity, and -Infinity as distinct unquoted literal tokens instead of collapsing them via
`JSON.stringify`, then a live field tampered between a non-finite value and `null` (or
between two non-finite values) is detected — subject to byte-identical output for every
existing finite/string/bool/null/array/object value, and 0 regressions on every
legitimately-signed existing receipt. Frozen before implementation; not modified after.
