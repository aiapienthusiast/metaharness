# MCP Scaffolding Security SOTA Report — 2026-10-18

TL;DR: MetaHarness's CLI scaffolder (`npx metaharness <name>`) registers a self-referential MCP server in `.claude/settings.json` for every default (`claude-code`-hosted) harness, but never wrote the companion `.harness/mcp-policy.json` default-deny policy that ADR-022 (Accepted, 2026-06-14) mandates — so `harness mcp-scan` flagged every fresh scaffold HIGH ("MCP server with no policy") the moment a user ran it. Disclosed-but-not-fixed since 2026-09-08 (issue #297, scored 3.60 that night, deferred as "too broad"). Tonight: found the exact single choke point, closed it with a 37-line, test-covered diff, verified no regression on the one host (`rvm`) that doesn't actually register MCP. 2026 external research (3 independent sources: OWASP Agentic Top 10, Cloud Security Alliance draft MCP guide, Wiz) converges on default-deny being the baseline industry expectation, with two real 2026 CVEs (CVSS ≥8) showing what this exact failure shape (governed primitive exists, not wired to the default path) costs when internet-facing.

## MetaHarness Current Capability

ADR-022 (Accepted) already specifies the exact safe-default MCP policy JSON and a static scanner (`mcp-scan`) that enforces it as a CI-able gate. The *scanner* and the *web-UI generator* (per ADR-022's own test contract, `apps/web-ui/src/generator/__tests__/mcp.test.ts`) already honor this. The **CLI scaffolder** (`create-agent-harness`, the actual `npx metaharness` entry point most users run) did not: `mcp: 'local'` is hardcoded at the `hostConfigFiles()` call site (`packages/create-agent-harness/src/index.ts`), unconditionally registering an MCP server, with zero writer for `.harness/mcp-policy.json` anywhere in the CLI path (confirmed: every reference to that path in `src/` was a *reader* — `mcp-scan.ts`, `threat-model.ts`, `oia-manifest.ts`, `score.ts` — never a writer).

## Hypothesis

Given a harness scaffolded by `npx metaharness <name>` with any host set that ends up registering an MCP server (today: every scaffold using the default `claude-code` host, confirmed across all 20 shipped templates), when the generator additionally emits ADR-022's default-deny `.harness/mcp-policy.json` gated on the SAME registration signal `mcp-scan` itself uses, then `harness mcp-scan`'s worst-severity verdict for that scaffold drops from `high` (finding `no-policy`) to `low`/`info`, relative to the current baseline (`high` on every default scaffold today), subject to: (a) zero regression on `rvm`/`pi-dev`/other hosts that register no MCP server at all — the policy file must NOT appear for them; (b) the full existing test suite (627 tests) stays green; (c) the new file is covered by `.harness/manifest.json`'s provenance hashes like every other rendered file.
