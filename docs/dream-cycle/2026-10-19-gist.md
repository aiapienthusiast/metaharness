# host-adapters (SDK) SOTA Report — 2026-10-19

TL;DR: `@metaharness/sdk`'s own README documents five authoring-time safety
guarantees ("Forgot description? Throws", kebab-case enforcement, name
collision detection), but the implementation only delivers two of them
consistently. `defineHarness()` never checks `description`, despite the
README's own row claiming it throws — and the SDK's existing test suite
never tests that row, so the gap shipped silently. `defineTool`,
`defineHook`, and `defineMcpServer` skip the `ensureKebab()` check that
`defineAgent`/`defineSkill`/`defineHarness` all enforce, and
`defineHarness()`'s collision detector only covers agent/skill names, never
tool or MCP-server names. Fixed all three gaps with the SDK's own existing
helpers — no new validation philosophy, just applying what the SDK already
enforces elsewhere, consistently. Disclosed, not fixed tonight: a latent
lazy-async-singleton race in `kernel-js` (`self-evolution.ts`'s
`ensureLoaded()`, `memory-rvf.ts`'s `ensure(ns)`) — well-researched tonight
(see below) but deliberately deferred given the standing PR review backlog.

## MetaHarness Current Capability

`packages/sdk/src/index.ts`'s `defineHarness()` validates the harness name
(`ensureKebab`) and agent/skill name collisions, but never checks
`description` — even though `README.md:46` documents "Forgot description?
Generated harness ships empty | Throws" as a guarantee, and the existing
test suite (`__tests__/sdk.test.ts`) tests every other README row
(kebab-case, systemPrompt, tier, agent/skill collision) except this one.
`defineTool`/`defineHook`/`defineMcpServer` validate their own required
fields but never call the shared `ensureKebab()` helper `defineAgent` and
`defineSkill` both use — so `defineTool({name: 'Bad Name!', ...})` silently
succeeds today. `defineHarness()`'s collision detector only builds
`agentNames`/`skillNames` sets; a `tools` or `mcpServers` array with two
entries of the same `name` passes silently through to the kernel.

**Why most rows read "none" rather than a direct match:** MetaHarness pairs
adaptive tier routing with genuine multi-host coding-agent scaffolding
(Claude Code/Codex/Copilot/pi.dev/Hermes/OpenClaw/RVM/GitHub Actions) and an
opt-in native/WASM backend; no competitor found combines both. The routing
*idea* itself is not novel — academic bandit/RL formulations (TRACE-Router,
HierRouter, BayesianRouter, LinUCB-AAAI-2026) have moved well past this
repo's EMA fallback — but none of that research literature, nor any named
competitor, documents how concurrent calls affect routing-state updates.
That blind spot is industry-wide, not MetaHarness-specific; `aisuite`'s open
TODO is the only public acknowledgment of the underlying bug class.

## Hypothesis

Given a harness author who calls `defineHarness()` with a missing
`description`, or `defineTool()`/`defineHook()`/`defineMcpServer()` with a
non-kebab-case `name`, or a `defineHarness()` call whose `tools` or
`mcpServers` arrays contain two entries sharing the same `name`, when
tonight's candidate is applied, then each call should throw a descriptive
`Error` synchronously at definition time instead of silently returning a
frozen object that will reach the kernel malformed, subject to: (a) every
currently-passing SDK test keeps passing unchanged; (b) no currently-valid
harness definition (name, kebab-case, non-empty fields, no collisions)
starts throwing; (c) zero changes to `@metaharness/kernel` or any
`HarnessDef`/`AgentDef`/etc. type shape.

## Benchmarks / Evaluation

**Candidate**: `packages/sdk/src/index.ts` — `defineHarness()` now requires
non-empty `description`; `defineTool`/`defineHook`/`defineMcpServer` now
call `ensureKebab()` on their `name`; `defineHarness()`'s collision pass now
also tracks `toolNames`/`mcpServerNames`. ~25 changed lines. New tests in
`packages/sdk/__tests__/sdk.test.ts` (+6 cases) directly exercising each
README row that lacked coverage.

- **Baseline** (current `main`): all 6 new assertions fail — `defineHarness({name:'h', agents:[], skills:[], description:''})` returns a frozen object instead of throwing; `defineTool({name:'Bad Name', ...})` returns instead of throwing; two tools/mcpServers named `'dup'` both pass through `defineHarness()` silently.
- **Candidate**: `packages/sdk` test suite — see Evaluation Receipt below for exact before/after counts.
- **Downstream sweep**: every in-repo consumer of `@metaharness/sdk` re-run to confirm 0 regressions (no existing valid definitions in examples/fixtures newly throw).
