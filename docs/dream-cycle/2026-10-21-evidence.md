## OBSERVATION

`@metaharness/flywheel`'s `canon()` (packages/flywheel/src/receipts.ts) is the single
JSON-canonicalization choke point every signed `PromotionReceipt`, `verifyReplayBundle`'s
`sealedFieldsAuthentic` check, and `multigeneration-proof.ts`'s `validAttestation` route
through. Pre-fix, it fell through to `JSON.stringify(v)` for any non-object value.

```
$ node -e "const {canon}=require('./packages/flywheel/dist/cjs/receipts.js');
  console.log(canon(NaN), canon(Infinity), canon(-Infinity), canon(null));"
null null null null
```

## INFERENCE

The collision is reachable, not merely theoretical, for any consumer that calls
`verifyReplayBundle`/`verifyReceipt`/`multigeneration-proof.ts`'s `validAttestation`
directly as a library function — which is the primary advertised use case (ADR-235: "an
external reviewer establishes the run with no trust in the producer"). The CLI path alone
is additionally protected by `validate-bundle.ts`'s `isFiniteBoundedNumber` checks (wired
only into `cli.ts`'s `loadBundle()`), but `validateReplayBundle` and `verifyReplayBundle`
are independently exported from `index.ts` and nothing requires a library caller to run the
former before the latter — confirmed by reading `index.ts`'s exports and `cli.ts`'s
`loadBundle()`. `MultiGenerationEvidence` has no equivalent validator at all.

A legitimately-signed non-finite value is plausible, not just adversarial: `primaryDelta =
candidate.primary - baseline.primary` (run.ts:194) and a Score's `primary` field are not
range-validated before signing in the live run loop — only `meetsPromotionRule`'s
`isValidScore` validates at GATE time, which is a different call site from receipt signing.

## HYPOTHESIS (frozen before implementation, STEP 3.3)

> Given a signed `PromotionReceipt` or sealed-field-authenticity check (`sealedFieldsAuthentic`
> in replay.ts, `validAttestation` in multigeneration-proof.ts) that compares a live numeric
> field against its `canon()`-encoded signed counterpart, when `canon()` is hardened to encode
> `NaN`, `Infinity`, and `-Infinity` as distinct, unambiguous literal tokens (rather than
> collapsing them to `null` via `JSON.stringify`), then a live field silently tampered between
> a non-finite value and `null` (or between two different non-finite values) is detected,
> subject to: (a) byte-identical `canon()` output for every existing finite number, string,
> boolean, null, array, and object; (b) every legitimately-signed existing receipt continues
> to verify unchanged; (c) the new tokens are collision-free against every other value `canon()`
> can produce.

Not modified after evaluation began. Not falsified — evidence above supports it.

## DECISION

**ACCEPT.** Evidence: evaluated above. Verdict: ACCEPT (independently confirmed). Effect:
closes a real tamper-evidence gap in the package's core trust primitive, 0 regressions at
every tier measured, no regressions, additive-only diff (76 insertions / 1 deletion, 2
files). Reward-hack check: clear (diff is additive, no test/threshold/gold weakened).
Security review: this candidate *is* the security hardening — see gist for CVE/competitor
context (RFC 8785 JCS explicitly forbids non-finite numbers for this exact reason).

## Disclosed, not fixed tonight (future-night candidates)

1. `packages/avo/src/flywheelGate.ts:29` and `packages/turn-credit/src/receipt.ts:13` each
   ship their OWN separate, still-colliding `canon()` duplicate (independently confirmed by
   this session AND the independent critic) — same bug class, different package, same class
   already flagged for the depth-recursion variant by 2026-10-16's #406 (still unmerged).
2. `validateReplayBundle`'s fail-closed numeric-domain boundary lives only in `cli.ts`'s
   `loadBundle()`, not in `verifyReplayBundle()`/`verifyMultiGenerationEvidence()` themselves
   — any of the ≥14 known direct/programmatic callers (per #406's own finding) bypass it
   entirely. `MultiGenerationEvidence` (ADR-318) has no equivalent validator at all. A larger,
   structural fix (wiring validation into the library functions themselves, not just the CLI)
   is a good candidate for a near-future flywheel-promotion night.
3. `canon(new Date(x))` → `"{}"` (Dates have no own enumerable keys) — pre-existing, found by
   the independent critic, orthogonal to tonight's fix, not a regression it introduces.
